# Brief для агента (floorplan → 3D) — не жёсткий закон, а рабочий контракт

Автор: внешний review (Grok Bot) по просьбе владельца. Рассмотри критически, но не игнорируй KPI.

## Цель прямо сейчас
На 2–3 приложенных чертежах:
1. стены лежат на подложке (тот же масштаб/origin, что и plan guide);
2. двери/окна/проёмы только где нарисовано — ничего не додумывать;
3. без фантазийных комнат 1 м², окон в коридоре и т.п.;
4. UI viewer-only уже ок — **не трогать**, пока 1–3 не зелёные.

## СТОП
- Стоп широкий ресёрч Pascal internals (sqlite, mcp storage, camera controls, wiki слоями).
- Стоп частные эвристики под одну жалобу (если коридор → дверь, «обязательный вход в комнату», отсев окон по типу комнаты и т.п.).
- Стоп объявлять «готово» без артефактов проверки.

## Обязательный цикл (в этом порядке)
1. **Сырой JSON vision** по провальному чертежу (сохрани в файл/лог job: observation + extract).
2. **Оверлей**: полигоны комнат / стены / openings на исходной картинке (PNG). Если оверлей врёт — проблема в vision/scale до 3D.
3. Если JSON/оверлей врёт → чинить **модель / two-pass промпт / slug OpenRouter**, не build-scene эвристиками.
4. Если оверлей ок, а 3D нет → только тогда transform guide↔walls, с численной сверкой (углы комнат vs метры/пиксели).
5. Повторить на 2–3 разных чертежах из вложений пользователя. Универсально, без подгонки под один план.

## Уже принятые решения (не переоткрывать без причины)
- Продукт в pps/editor, OpenRouter (OPENROUTER_API_KEY), не MCP sampling.
- Свой uild-scene (не create_room MCP) — ок.
- Viewer после импорта, не CAD; editor отдельной кнопкой — ок.
- Не додумывать двери; только чертёж.
- Encoding UI — не баг рантайма.

## Отчёт владельцу
Коротко: что показал оверлей, где ломается (vision vs transform), какой следующий минимальный шаг. Без портянки ресёрча.
